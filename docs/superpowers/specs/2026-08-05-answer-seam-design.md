# The answer seam: Orbit hears the reply to its own question

**Date:** 5 August 2026 · **Slice branch:** `feat/answer-seam` · **Status:** approved by the product owner in the brainstorming session of 5 Aug 2026.

## What this slice is

The wrong-day retry taught Orbit to ask "What day works better?" when a day-blocked idea would otherwise have cleared the bar. The machinery around that ask is deterministic and proven. The conversational half is not: a member answering "Saturday?" or "saturday works for me" is read by the recognizer as a request to change some existing plan (four of five runs answered "I can't move it to another day yet") or as nothing at all (the fifth run, and all five runs on the fuller sentence). Orbit asks a question and then ignores the answer, which is the single worst thing an assistant can do right after speaking.

This slice fixes recognition and touches nothing downstream. It fails today for two specific reasons, both self-inflicted rules doing their jobs in the wrong place: the recognizer only knows two actionable message kinds (fresh idea, change request), and "Saturday?" cannot be a fresh idea because the recognizer is rightly forbidden from inventing an activity the message never named; meanwhile it was separately taught that a named weekday usually means "move a plan to that day," so the change reading wins even over an empty calendar. Nothing ever told it that Orbit itself might have a question open.

The fix follows the owner's scaffolding principle and makes Orbit *more* deterministic, not less: the model gains exactly one new judgment call ("this reply answers Orbit's open question, and the day named is Saturday"), and every fact the new gauge is built from is carried from stored state, never re-derived by the model. The prompt language is general ("when Orbit has a question open, a short reply is probably an answer to it") so a future kind of Orbit question plugs into the same context slot with one line; the machinery is deliberately not a framework, because only one question type exists today.

## Settled decisions (do not relitigate)

1. **A third intent class: "answer to Orbit's open question."** Alongside fresh idea and change request. The model's whole contribution is the answer-ness judgment plus two extractable facts: the day, when exactly one is named, and a stated time, when one is given. The activity is never the model's to name; it is carried from the failed gauge the open question belongs to. Chosen over loosening the never-invent-an-activity rule (the model re-deriving a stored fact is the failure pattern behind the CLIMBING→CLIMB scar) and over a no-model deterministic matcher (pure code cannot tell "Saturday?" from "saturday was fun," and that look-alike is exactly what the bench protects at 5/5).
2. **"An ask is open" is derived from existing state; no new fields, no migration expected.** The failed gauge already carries the ask-message marker. The ask is open from the moment it posts until any new gauge for the same activity exists, whether a member's answer or Orbit's own next-evening guess; this is the same answered-test the guess suppression already uses, so the window self-closes within about a day and the two mechanisms can never disagree about whether the question was answered.
3. **The model's "answer" claim is only trusted inside that window.** Deterministic code independently confirms an open ask before acting; an answer claim arriving when no ask is open is discarded. The new class can never fire outside its window, whatever the model says.
4. **While an ask is open, the answer reading beats the change reading.** Orbit's own question is the loudest context on screen, and a short day reply in its shadow is an answer, not a plan edit. This is a defined precedence, not a widening of the known both-true discard: the queued both-true slice (spark versus change) is untouched, and its scope does not grow here.
5. **The answer gauge inherits the original idea's time; a stated time wins.** "Saturday?" after a failed "beers at 8" is an 8pm Saturday gauge, by copying the original gauge's stored proposed time, never re-deriving it; "Saturday at 9?" resolves 9 through the existing time ladder (am/pm from the activity, the existing disclosure rules) and wins. **This amends the wrong-day-retry spec's decision 4** ("a member's answer rides the existing spark path, unchanged"): the ride is no longer unchanged, because the ordinary fresh-idea path would re-derive a generic default time from a message that names none, and the group already agreed on 8. The guess already carried time this way; now both revival paths follow one rule. Making the matching edit to CLAUDE.md's settled list is the slice's first execution task, per the standing rules-file rule.
6. **An answer naming no single day gets the same-weekday-next-week rule, nobody seeded.** "next week?" or "any day works" is still an answer; Orbit picks the day exactly as the guess would (Friday failed, next Friday proposed), reusing the guess's date rule and its named constant rather than inventing a second revival heuristic, and reading literally right for "next week." The generic fresh-idea fallback (Fri evening/Sat morning) is wrong here: it could answer "next week?" after a failed Friday with a Saturday, which reads as Orbit not listening. Seeding is unchanged: the existing exactly-one-day rule already withholds the seed when the member named no single day.
7. **Everything else about the new gauge is the existing spark path.** Fresh gauge, votes never carry, the namer seeded as the first yes when they named exactly one day, full gauge rights (a member-named revival can earn its own retry later; the settled whose-move-it-was rule). The old gauge stays closed forever; "a gauge whose day has passed is dead" is still not bent.
8. **Guess suppression is automatic, not new code.** The answer gauge is precisely what the existing "was it answered?" check looks for, so recognizing an answer cancels the pending guess through machinery that already shipped and is already tested.
9. **Zero new model calls, negligible cost delta.** The same single per-message detection call the product already pays for; the prompt grows by a few lines, and the open-question context line is included only while an ask is actually open. One additional cheap database check per member message to derive the window. No spending-ceiling implication.
10. **This slice updates the records it touches, in the same PR:** the CLAUDE.md settled-list amendment (first task, decision 5), a new row in the build-notes speak-or-stay-quiet register for the answer class and its precedence (per that register's standing rule), the "Where the build is" rewrite at the slice boundary, and the build-notes §11 entry with the bench before/after scoreboard.

## Not in this slice (every exclusion names its home)

- **A second member replying with a different day once a new gauge is live** ("Sunday better" after Saturday's gauge opened): a day comment against a live gauge is a different seam needing its own product decisions, none of whose machinery exists. Queued at the owner's direction as its own future slice ("day comment on a live gauge"); today that person's path is the chips and the can't-that-day vote.
- **The older ambiguous-bucket bench cases** (the bucket sits at 1 of 4; the non-retry cases are older seams): separate recognition tuning, bench-driven as real failure shapes accrue. Mixing them in would muddy what this slice proves.
- **The both-true claim** (a message read as both fresh idea and change request is discarded whole): already queued as its own slice by the owner, 29 July. Decision 4 defines precedence for the *answer* class only and does not touch it.
- **An outstanding-question framework or registry:** deliberately not built. The general prompt language is the whole generality until a second ask type exists; a future ask type adds one context line, and building more now would be structure on one example.
- **Verbal RSVP:** untouched, tracked where CLAUDE.md already tracks it.
- **No copy changes** to the ask, the guess, the goodbye, or any existing bump.

## How this will be verified (written before any code)

**Suite baseline, recorded:** 605 tests across 40 files, all passing, run on this branch on 5 Aug 2026 before any code, exactly matching the finishing number the wrong-day-retry slice left in build-notes §11. No pre-existing failure is carried.

**Bench, the slice's primary evidence, red on day one:** the two must-recognize cases (`retry-answer-bare-day`, `retry-answer-day-works`) sit at 0/5 and 0/5 from the wrong-day-retry slice's recorded run. Before the fix, a cheap filtered re-run of the three retry-answer cases confirms they are still red. After: those two at 5/5, `retry-answer-next-week` passing as a spark with no single day, the look-alike `retry-answer-nostalgia` holding at 5/5, every other must-stay-quiet case holding its bar, and no must-recognize case regressing. The full before/after scoreboard goes to build-notes §11. The bench stays outside the test suite, same as always: it costs money and hits the network.

**Automated, every test written first and watched failing:**

- The open-ask window, both ways: derived open when the marker is set and no same-activity gauge followed; derived closed by a member's answer gauge, by the guess gauge, and by a different-activity gauge *not* closing it (matching the answered-rule this reuses).
- The trust guard: an "answer" claim with no open ask normalizes to nothing; the precedence rule when the model flags answer alongside change; day bounds and time format validation on the new fields.
- The build from stored facts: activity carried verbatim from the failed gauge, time copied from its stored proposed time, a stated time winning through the existing ladder, date at the named day's next occurrence, same-weekday-next-week when no single day was named (correct across a month boundary and in a non-UTC group timezone), seeding per the exactly-one-day rule, refusal when the resolved instant is past.
- Prompt-pinning tests extended for the new class language, alongside the existing pinned substrings.

**By hand, in the browser against dev-test,** staged versus lived stated plainly in the PR: a staged group with a failed gauge and its posted ask; a member replying "Saturday?" and the new gauge appearing with the right day, the carried time, and the namer seeded; a staged next-evening sweep producing no guess (suppression); "saturday was fun" producing nothing; and a "next week?" reply opening the same-weekday-next-week gauge with nobody seeded. The staging extends the committed `scripts/qa-stage-retry.ts` precedent, with `npm run db:which` first, every time. The QA script lands in the PR body and the chat handoff, about five minutes.

## Debt this slice expects to open

- **Recognition is a rate, not a guarantee.** The bench proves a rate over N runs, never certainty; the deterministic next-evening guess remains the net under every conversational miss, which is what keeps the feature coherent on a bad run. Recorded as the standing shape of every model-dependent seam.
- **The context slot is fed by one ask type, by hand.** A future slice adding a new kind of Orbit question must remember to feed the open-question slot, or its answers die exactly the way this slice's did. The register row is the tripwire; still worth naming as the cost of choosing no framework.
- **The precedence rule is one more speak-or-stay-quiet decision,** live only inside the ask's roughly one-day window. Its register row keeps it visible; wrong precedence would read as Orbit hijacking a plan-edit request into a revival, which the stay-quiet bench cases bound but cannot eliminate.
- **The queued second-member seam got more visible.** Recognizing the first answer makes the unrecognized second one ("Sunday better") stand out more than when both died equally. Queued above with a named home; the pressure to build it will come from real groups quickly.
